**BioScribe Phase 2 — scientific integrity, identity, validation evidence, and privacy**

Initial review: 14 October 2026. Amended: 15 October 2026. Basis: static inspection of the current working tree and the primary references linked below. Phase 1 established inventory, not scientific validity. The prior minimal runtime probe stalled and was interrupted; startup and successful test execution remain unverified. This amendment ran no application tests and changed no application source code. The acceptance criteria below are requirements, not implemented controls or passing results.

**Disposition: scientific release and sensitive-data intake remain blocked.** This is an audit disposition; this review has not changed or disabled the running product. Existing local modifications are preserved. Six findings follow the six requested mandates rather than the earlier limit of three to five findings. The amended gates below supersede broader earlier acceptance wording.

Severity definitions: **Critical** blocks release of the affected scientific claims or workflow. **High** requires correction before the affected capability is offered. Privacy severity is conditional on intended deployment and data relationships; no actual PHI disclosure has been established.

| Finding | Severity | Release gate |
| --- | --- | --- |
| F1 — Results lack authoritative experiment attribution | Critical | Every displayed/exported result resolves to its authorized persisted run. |
| F2 — Unsupported affinity, confidence, toxicity and pharmacokinetic claims | Critical | Affinity arithmetic is only an unvalidated dimensionless heuristic; unsupported toxicity and pharmacokinetic assessments are `not_assessed`. |
| F3 — Named methods and structural interpretations do not match the computation | High; safety claims also fall under Critical F2 | Verify method fidelity separately from predictive validation; retain overlapping composition descriptors without inferred structure. |
| F4 — Biological and chemical identity are underspecified | High | Validate identity, transformations, supported input classes, and analysis coverage before computation. |

**F1 — Results lack authoritative experiment attribution.**

**Evidence and affected paths →** The [results page](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/app/results/[id]/page.tsx:16) creates fixed findings including validated affinities and confirmed synthesis feasibility, then [renders that object](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/app/results/[id]/page.tsx:138). The [wizard](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/app/pipeline/new/page.tsx:68) maps four example IDs to sequences, stores a response in browser session storage, and navigates to `/results/1`. It does not submit the selected upload or analysis options. The [standard launcher](E:/Bioscribe/CascadeProjects/windsurf-project/start-backend.ps1:27) and [Docker image](E:/Bioscribe/CascadeProjects/windsurf-project/Dockerfile:58) select `main_real.py`; the [shared client](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/lib/api.ts:130) expects the newer nested contract. The [new API](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:343) generates IDs with only one-second time resolution and returns results without persisting a run. Legacy [exports](E:/Bioscribe/CascadeProjects/windsurf-project/backend/main.py:278) form another result path.

**Scientific/privacy consequence →** A researcher can attribute an unrelated finding to their target, configuration, or uploaded experiment. A nominally successful request, browser navigation, and displayed completion state are not a chain of evidence. Retrying or running concurrently cannot be audited reliably using the current timestamp ID.

**Required change →** Select one authoritative versioned backend contract and application composition. All launch paths must select it or an explicitly identified demo application. Validate requests and responses against strict schemas; generate frontend types and validate received data at runtime. Persist an immutable input/configuration snapshot before queuing a run. Link input identity, method versions, each step output, rendered values, and exports through a collision-resistant `run_id` and artifact identifiers. Distinguish execution state from evidence status: a computationally successful heuristic remains unvalidated. Use explicit queued/running/succeeded/failed/cancelled/rejected states and per-step failures; missing and unauthorized runs return explicit access-appropriate states, with no example fallback. Demonstrations require separate routes/data namespaces, visible labels, and export labels. Unsupported wizard options must be rejected or disabled.

**Acceptance criterion →** Two deliberately distinct submissions receive different persistent IDs and retain the correct inputs, configuration, artifacts, and result hashes through reload, worker restart, and export. API, UI and export agree on the same run and method versions. Concurrent submissions cannot overwrite a run; idempotent retries refer to the original request, while conflicting payloads are rejected. Unknown, failed, cancelled, unauthorized, stale-schema, and missing-artifact cases never render successful scientific findings. Demo fixtures never enter a research run's evidence. Contract checks cover every supported launch path and frontend workflow, including actual file uploads and each offered option.

**F2 — Unsupported affinity, uncertainty, toxicity and pharmacokinetic interpretations.**

**Evidence and affected paths →** The [scorer](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/docking_engine.py:105) labels hand-weighted arithmetic as kcal/mol and clips its output to a plausible-looking range. Its [confidence](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/docking_engine.py:179) is a formula of QED and motif presence, without empirical error calibration. Larger absolute molecular-weight and TPSA deviations make negative-weight terms more negative; the ascending score sort therefore rewards those deviations, opposite the stated optimality rationale, until clipping masks the effect. This is a static mathematical inference from the code, not a measured model-performance result. The [API summary](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:340), [client types](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/lib/api.ts:138), [docking display](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/components/tabs/DockingTab.tsx:72), and [workbench](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/components/SimpleWorkbench.tsx:76) propagate this meaning. The workbench also fixes average confidence at 0.85. Ligand efficiency is derived from the unsupported energy value.

The [toxicity logic](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/admet_engine.py:263) silently skips an uncompiled pattern, equates uppercase `N` in a SMILES string plus a logP threshold with basic nitrogen, and converts alert counts into Ames and overall toxicity categories, including `Low`. A character search cannot establish chemical basicity: bonding, charge, protonation and aromatic representation matter. The [excretion logic](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/admet_engine.py:222) turns `2 + 1.5 * logP + 0.005 * MW`, clipped to 0.5–24, into half-life hours. The [metabolism logic](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/admet_engine.py:176) similarly labels CYP substrate status, inhibition risk and metabolic stability using descriptors and motif counts. No endpoint-specific validation is supplied by these computations.

**Scientific/privacy consequence →** The numbers can be mistaken for target-specific binding measurements or validated predictions and used to prioritize synthesis or experiments. A confidence percentage suggests a known error rate that has not been established. Relabeling the number alone does not correct the heuristic's inverted terms or establish ranking utility. Low alert counts can falsely reassure users about safety; arbitrary half-life hours can be mistaken for exposure or dosing evidence. Absence of a match in a limited rule set is not evidence of absent toxicity.

**Required change →** Retain the scorer only as `prioritization_heuristic`, explicitly unvalidated and dimensionless, with a documented score direction and algorithm version. Remove affinity units, confidence probabilities, inferred energy-based ligand efficiency, pose/docking success claims, and any Kd/Ki interpretation derived from it across APIs, UI, summaries and exports. Check term directions and clipping behavior. For any future predictive endpoint, define target, assay endpoint, units, conditions, population, model/data version, applicability domain, and an abstention policy. Validate uncertainty separately from the point prediction. OECD requires a defined endpoint, transparent algorithm, applicability domain and evidence of fit, robustness and predictivity; referring to QSAR does not supply that evidence. [OECD validation guidance](https://one.oecd.org/document/env/jm/mono%282007%292/en/pdf).

**Acceptance criterion →** Every reachable representation of this heuristic has dimensionless units, unvalidated status, a method version and no calibrated-confidence claim or physical-affinity derivative. Monotonicity and boundary fixtures agree with the documented heuristic, including saturation and ties. A predictive endpoint remains unavailable unless its validation record contains predeclared numerical acceptance thresholds, a justified sample-size/precision plan, leakage-controlled held-out evaluation, comparison to relevant baselines, uncertainty results when claimed, and a verified applicability-domain decision. Insufficient or out-of-domain evidence triggers abstention rather than a plausible number. Passing software tests alone never grants predictive status.

**Additional required change — ADMET containment →** Separate `structural_alert_observations` from `toxicity_assessment` and `pharmacokinetic_assessment`. Observations identify the versioned rule, matched atoms, input molecular identity, scan coverage and execution status; rule names must not assert that the molecule is mutagenic, carcinogenic or safe. Remove the basic-nitrogen assertion from the lexical test. Until endpoint-specific validation supports the relevant input domain, toxicity and pharmacokinetic prediction values are null with `assessment_status=not_assessed` and a reason. This includes half-life, clearance, elimination route and metabolic predictions, not just the displayed overall label. Validly computed molecular descriptors may remain descriptors. Neither a disclaimer beside a numeric prediction nor a renamed safety score satisfies this gate. Endpoint and domain requirements follow the [OECD QSAR framework](https://www.oecd.org/en/topics/sub-issues/assessment-of-chemicals/quantitative-structure-activity-relationships-project.html).

**Additional acceptance criterion →** Contract, UI and export fixtures independently cover completed scans with zero/one/multiple matches, invalid rule compilation, calculation failure, unavailable models, unsupported molecules and out-of-domain inputs. A zero-match result says only that no matches were found in the identified, successfully executed rule set. A failed or partial scan cannot masquerade as an empty completed scan. Every case without applicable predictive validation returns `not_assessed` with null toxicity/PK values and a specific reason; none produces `Low`, `safe`, estimated hours, or equivalent reassuring wording. Even a positive structural alert remains an observation rather than an assessed toxicity class. Future Ames, hERG and half-life claims each require their own endpoint definition, assay/species/context and units, label provenance, applicability domain and evaluation record; evidence is not transferable between them.

**F3 — Named methods do not consistently correspond to implemented algorithms.**

**Evidence and affected paths →** In [ADMET processing](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/admet_engine.py:83), `ap = 0` removes aromatic proportion from the formula, although the result retains the ESOL model label. Delaney describes aromatic heavy-atom proportion as a predictor. Relative to the equation written in this code, omitting the term increases logS by `0.74 × AP`; that observation does not certify the remaining coefficients or RDKit descriptor substitution as the original model. [Delaney, 2004](https://pubmed.ncbi.nlm.nih.gov/15154768/).

The [kinase regex](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:372) is `[LIVMFYC].G.{2}G.{1,2}[GSTA].{3,6}K`. The cited PS00107 instead specifies restricted residue sets, excluded residues, a different glycine arrangement, and a variable span of 5–18 residues within a longer signature. This is not the referenced pattern. [PROSITE PS00107 documentation](https://prosite.expasy.org/PDOC00100). Its motif results subsequently guide [scaffold preferences](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/molecule_engine.py:194) and scoring. A motif match is also not a measured 3D binding pocket or proof of catalytic activity.

Other exposed labels require the same audit: [per-residue propensity lookup](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:222), [ADMET threshold rules](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/admet_engine.py:99), [synthetic-accessibility approximation](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/molecule_engine.py:455), and the combined [API methods field](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:362). These are audit targets; this review has not established correspondence to all their named sources.

The [secondary-structure output](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:163) treats composition-derived fractions as a structural partition and calculates coil by subtraction. Biopython's helix and sheet residue groups overlap at leucine. Consequently, `LLLLLLLLLL` gives helix-group fraction 1, sheet-group fraction 1, turn-group fraction 0 and the inspected complement `1 - 1 - 1 - 0 = -1`. This is a static counterexample, not a runtime result. Biopython also documents reversed helix/sheet return ordering before version 1.82. [Biopython definitions](https://biopython.org/docs/latest/api/Bio.SeqUtils.ProtParam.html). Dependency declarations disagree: [requirements.txt](E:/Bioscribe/CascadeProjects/windsurf-project/backend/requirements.txt:12) pins 1.81, [requirements-production.txt](E:/Bioscribe/CascadeProjects/windsurf-project/backend/requirements-production.txt:22) pins 1.83, and [requirements_genuine.txt](E:/Bioscribe/CascadeProjects/windsurf-project/backend/requirements_genuine.txt:14) permits versions from 1.81. The [frontend contract](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/lib/api.ts:72) retains `dominant_structure`.

**Scientific/privacy consequence →** A published method's identity and credibility are attached to a different computation. Errors propagate into candidate selection, inferred solubility, and apparent target suitability. Chemical sanitization and a complexity score do not establish synthesis feasibility. Overlapping residue-composition groups cannot establish structural occupancy, dominant folding or disorder, even when the descriptor calculation faithfully implements its library.

**Required change →** Introduce a method registry and require every result to reference a pinned registry record. Correct the implementation to the chosen reference or assign a distinct modified-method identity with its own validation. Audit descriptor definitions, coefficients, units, preprocessing, matching semantics, reference-data releases and numerical tolerances. Validate scientific performance separately from implementation fidelity.

| Required registry field group | Required content |
| --- | --- |
| Identity | Method ID, implementation version, source/build digest, dependency versions, owner/reviewer. |
| Reference | DOI/accession, exact reference or database release, retrieval date and retained snapshot/digest where permitted. |
| Algorithm | Formula or pattern, parameter values, descriptor implementations, input/output schemas and units. |
| Interpretation | Intended endpoint, assumptions, applicability limits, unsupported inputs, coverage and abstention policy. |
| Implementation fidelity | Reference correspondence, independently derived fixtures, expected values/tolerances, check results and review record. Passing this does not establish predictive validity. |
| Predictive validation | Separate endpoint-specific record with dataset/split provenance, thresholds, measured results, domain and validity decision; explicit absence/reason when unavailable or not applicable. |

**Acceptance criterion →** Each displayed scientific field references a registry identity with separate implementation-fidelity and predictive-validation states and satisfies the field-level contract below. Registry approval cannot grant predictive status. ESOL fixtures include aromatic and nonaromatic structures with independently established descriptor values; aromatic proportion is actually computed and its denominator declared. Reproducing the chosen reference includes all descriptors and coefficients, not just restoring this one term. PS00107 fixtures include reference positives/negatives, forbidden-residue substitutions, both variable-span boundaries and documented overlapping-match behavior; results match the pinned reference implementation. Any deliberate divergence carries a distinct name and version. No “validated synthesis” label is inferred from SMILES validity or a synthetic-accessibility heuristic.

**Additional required change and acceptance criterion — composition descriptors →** Rename the three values as overlapping residue-group composition descriptors, with the exact group definitions and denominator in the method record. Remove inferred coil and `dominant_structure` from API, client types, UI, summaries and exports; do not clamp a negative coil or renormalize the overlapping fractions into a partition. Pin one exact, tested Biopython release at or above 1.82 across supported launch paths and record it in artifacts. Phase 3 fixtures require `LLLLLLLLLL` to yield the independent group descriptors `(helix=1, turn=0, sheet=1)`, no coil and no structural verdict. Distinct helix-only, sheet-only and turn-only group fixtures must check tuple ordering against the selected release; the leucine example alone cannot detect an ordering swap. Each descriptor is bounded individually, but their sum need not equal one. Unsupported dependency versions fail startup/readiness explicitly. This correction does not validate the separate per-residue structural heuristic.

**Cross-cutting F1–F5 gate — evidence status belongs to each scientific output (Critical).**

**Evidence and affected paths →** The separate [API methods list](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:362), [protein output object](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:139), [ADMET output object](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/admet_engine.py:275) and [frontend result types](E:/Bioscribe/CascadeProjects/windsurf-project/bioscribe-ai/src/lib/api.ts:72) do not provide the required field-level evidence contract. The earlier phrase “approved registry identity” was insufficient: identity and implementation fidelity are different from empirical predictive validity.

**Scientific/privacy consequence →** A successful job, correctly implemented heuristic, or reviewer approval can appear to validate unrelated fields, silently promoting weak evidence into a scientific claim.

**Required change →** Enforce the following versioned envelope on every scientific field, including derived summaries, rather than merely on its parent run. Large arrays may share a referenced immutable envelope only where every covered element has the same method and evidence semantics; exceptions require explicit element/interval metadata.

| Field group | Required semantics |
| --- | --- |
| Identity and value | Run/artifact ID, input identity/hash, field identity, value or explicit null, endpoint/quantity and units. |
| Evidence category | Explicit category such as computed descriptor, structural-rule observation, unvalidated heuristic, model prediction, experimental observation or unverified extraction. A category alone is not a validation decision. |
| Method and fidelity | Method/version, build/dependency provenance and separate fidelity-check record/status. An unexecuted assessment identifies its assessment-policy version and the absent/unavailable model. |
| Validation | Applicable immutable endpoint-specific validation-record ID and decision, or null plus a reason; no generic run-wide validation flag. |
| Domain and coverage | In-domain/out-of-domain/undetermined/not-applicable decision with basis; analyzed and omitted inputs or intervals, completeness and reasons. |
| Assessment and execution | Assessment status (including `not_assessed` and `needs_review`) and reason distinct from computation state (`succeeded`, `failed`, `unavailable`, `unsupported_input`). A successful descriptor computation does not mean toxicity was assessed. |

**Acceptance criterion →** The authoritative schema and semantic validator reject a predictive assessment lacking a compatible validation record, endpoint, method version or supported domain. Version/endpoint mismatches, revoked validation, unknown domain and incomplete coverage outside the validated policy cannot inherit a validated label. No-evidence ADMET predictions remain null and `not_assessed`; a completed descriptor may retain its value with descriptor semantics and predictive validation marked not applicable. API responses, rendered states, summaries and exports preserve identical field evidence, reasons, versions and units. Fixtures mix validated and unvalidated fields in one successful run, exercise missing/invalid metadata and stale contracts, and prove that job completion, registry review and reviewer approval cannot bulk-upgrade evidence. A source-review decision may attest that an extraction matches its source; it cannot establish that the source's scientific claim is true. Missing evidence metadata fails closed rather than defaulting to validated.

**F4 — Biological input identity, transformations and coverage are incomplete.**

**Evidence and affected paths →** The [new input models](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:91) expose sequence/name/free-text organism without polymer type, accession version, taxonomy ID, record count or normalization history. The [parser](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:77) strips a leading header rather than producing explicit FASTA records. Older [validators](E:/Bioscribe/CascadeProjects/windsurf-project/backend/main_real.py:127) delete noncanonical characters; the new engine instead rejects them. The [per-residue structure array](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:228) stops at 500 residues. The [hydropathy window](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/protein_engine.py:205) excludes terminal positions. The legacy [ESM path](E:/Bioscribe/CascadeProjects/windsurf-project/backend/models/ai_molecular_engine.py:116) truncates tokens. [SMILES validation](E:/Bioscribe/CascadeProjects/windsurf-project/backend/engines/molecule_engine.py:527) sanitizes/canonicalizes but returns no explicit stereochemistry, charge, salt or tautomer policy record. The [pipeline summary length](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:346) counts raw input characters while protein analysis reports normalized residues.

**Scientific/privacy consequence →** The analyzed material can differ from what the user believes they submitted; discarded symbols and unreported coverage can hide important regions. A nucleotide string composed of A/C/G/T also fits the protein alphabet, so alphabet validation alone does not identify its polymer. Unsupported biological conclusions can be generated from insufficient context. Unstructured text also creates a separate identity and sensitive-data handling problem.

**Required change →** Use a biological input record containing declared polymer/input type, parsed record count, original and normalized identities/hashes, transformations, source accession/version and organism taxon ID. Permit explicit unknown/unavailable provenance with a reason for user-supplied constructs rather than inventing an accession. Define per-method handling of ambiguous residues, U/O and other nonstandard residues, gaps, stops, invalid encodings and malformed or multi-record FASTA. Preserve coordinate mappings and declare coordinate conventions. For molecules record isomeric identity, assigned/unassigned stereochemistry, formal charge, protonation assumptions, disconnected fragments, salt/parent selection, tautomer policy and each transformation's output identity. Do not silently discard chemical distinctions.

Require full sequence coverage or explicit analyzed intervals, omitted intervals/reasons, total length and completeness. Chunking, when valid for a method, must declare window/overlap/aggregation semantics. A protein-only submission cannot support a frameshift assessment: require nucleotide variant and appropriate versioned reference/transcript, strand, coding coordinates, frame and translation context, or return `unsupported_input`. Garbled notes enter `needs_review`, separate from sequence computation. Proposed LLM extractions remain unverified candidates with source document hashes, precise supporting spans, extraction version and reviewer/validator decisions; they cannot become scientific facts through a schema check alone.

**Acceptance criterion →** Fixtures cover single and multiple FASTA records, headers/line endings, malformed records, ambiguous/nonstandard residues, gaps/stops, declared nucleotide versus protein, and oversized inputs. Every accepted transformation is traceable; forbidden input is rejected explicitly. Lengths 499/500/501 and longer sequences yield complete results or exact partial-coverage metadata with visible missing regions. Enantiomers and unspecified stereochemistry are distinguished; salt, charge and tautomer changes follow recorded policy. Missing frameshift context yields unsupported status with no assessment. Unverified note extraction cannot populate verified result fields or exports, and source-span integrity must be checked before review can approve it.

**F5 — Benchmarks fabricate evidence and mis-handle statistical cases.**

**Evidence and affected paths →** The [benchmark service](E:/Bioscribe/CascadeProjects/windsurf-project/backend/services/benchmark_service.py:104) samples random metrics with fewer than three matched labels and [randomizes enrichment](E:/Bioscribe/CascadeProjects/windsurf-project/backend/services/benchmark_service.py:141) even when labels exist. Its ranking uses `sorted(...).index(...)` followed by a no-ties shortcut, and zero variance [returns Pearson zero](E:/Bioscribe/CascadeProjects/windsurf-project/backend/services/benchmark_service.py:120). [Truthiness filtering](E:/Bioscribe/CascadeProjects/windsurf-project/backend/services/benchmark_service.py:192) discards valid zero-valued labels. The same embedded ligand labels are reused across targets without assay-specific label records. [Screening types](E:/Bioscribe/CascadeProjects/windsurf-project/backend/services/screening_engines.py:22) describe truth as Kd/Ki and predicted scores as kcal/mol without an enforced conversion/endpoint contract. Vina/GNINA wrappers still produce simulated scores.

**Scientific/privacy consequence →** The purported validation can report success without evidence, compare incompatible endpoints, and overstate performance through invalid statistics or unsuitable labels. A named dataset or deterministic simulator does not establish predictive validity.

**Required change →** Separate synthetic software fixtures from scientific evaluation. Each label needs compound and target identity, endpoint, unit, assay conditions and relation/censoring, experimental source/version, quality status, and transformation history. Select the dataset and split to match the specific prediction task. Missing, incompatible, or inadequate evidence must yield a per-metric `insufficient_evidence`/`undefined` state and reason, with null value, not a fabricated number. Preserve usable sample counts and exclusions. Compute Spearman through average-rank correlation and treat constant-vector correlations as undefined, consistent with [SciPy ranking](https://docs.scipy.org/doc/scipy-1.11.4/reference/generated/scipy.stats.rankdata.html) and [correlation behavior](https://docs.scipy.org/doc/scipy-1.11.4/reference/generated/scipy.stats.pearsonr.html).

For enrichment, define activity and the eligible screened population first, then calculate `EF@k = (actives_in_top_k / k) / (actives_total / N)`. Document cutoff rounding, boundary ties and unlabeled compounds; report actual k and N. Zero actives makes this EF undefined. A 15-ligand sample cannot supply a literal 1% subset: any one-ligand approximation must be disclosed as its actual fraction and cannot replace a justified evaluation sample. Missing labels do not become inactive labels. RMSE requires compatible target endpoints/units; it is inappropriate for the dimensionless heuristic versus physical-affinity labels. Correlation may assess ordering with a declared direction, but does not establish energy calibration.

**Acceptance criterion →** Hand-derived and independent-library fixtures cover ties, constants, missing/nonfinite values, zero labels, zero actives, censored labels, invalid unit mixtures and small cutoffs. No metric is invented. Each reported metric includes eligibility status, paired/sample counts, exclusions, endpoint/units, method version and label manifest. Descriptive computability is distinguished from sufficient evidence for a claim; predeclared precision/power and leakage-control requirements govern the latter. A locked evaluation split cannot be reused for fitting or tuning. Any bootstrap/permutation procedure has a documented design and seed; legitimate resampling is not replaced by arbitrary random scores. Simulated engine runs remain visibly synthetic and cannot validate a real engine.

Dataset-task mapping required for later validation: deterministic descriptors use independent reference calculations; motif detection uses reviewed positives/negatives with pinned sequence/pattern releases; physical-affinity prediction uses compatible target–ligand experimental endpoints; virtual-screening enrichment uses appropriate active/inactive labels and selection provenance; ADMET endpoints need their own assay-specific labels and domain checks. Evidence for one endpoint cannot validate another.

**F6 — Durable provenance, protected access and compliance scope are not established.**

**Evidence and affected paths →** The [new pipeline](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:291) runs within the request and has no durable run/job store. The legacy [database adapter](E:/Bioscribe/CascadeProjects/windsurf-project/backend/database/mongodb.py:39) defaults to memory; [AtomNet projects](E:/Bioscribe/CascadeProjects/windsurf-project/backend/routers/atomnet_router.py:42) are also memory dictionaries. The [new error response](E:/Bioscribe/CascadeProjects/windsurf-project/backend/api_genuine.py:387) includes exception text and a traceback. Inspected route wiring lacks enforced authenticated principals and resource authorization. A legacy [remote inference path](E:/Bioscribe/CascadeProjects/windsurf-project/backend/models/ai_molecular_engine.py:90) sends sequences to an external provider when configured.

The [compliance status function](E:/Bioscribe/CascadeProjects/windsurf-project/backend/enterprise_compliance.py:394) hard-codes encryption at rest/in transit and enabled compliance categories; these are not deployment measurements. Its [signature function](E:/Bioscribe/CascadeProjects/windsurf-project/backend/enterprise_compliance.py:64) hashes caller-supplied identity/password/action without account verification, and the [route](E:/Bioscribe/CascadeProjects/windsurf-project/backend/compliance_endpoints.py:67) returns valid/Part-11 labeling. The [audit-chain hash](E:/Bioscribe/CascadeProjects/windsurf-project/backend/enterprise_compliance.py:79) omits old/new values and reason, although the event contains them. Those fields are therefore not protected by that hash. These are code-level weaknesses, not findings of actual disclosure or a determination that a regulation applies.

The [integrity verifier](E:/Bioscribe/CascadeProjects/windsurf-project/backend/enterprise_compliance.py:118) checks only the supplied in-memory list against itself. A retained valid prefix, including an empty list, passes its loop; a writer can also recompute an altered chain. This follows from static inspection. Hashing additional payload fields alone cannot detect tail deletion, reconstruction or restoration of an older internally consistent history.

**Scientific/privacy consequence →** Work or evidence can disappear on restart; results cannot reliably be reproduced, attributed to an authenticated actor, or investigated. If confidential or patient-linked data were accepted, the identified routes could expose data or metadata without the required access/egress boundary. Neither checksum chains nor compliance flags establish regulatory compliance or authenticated signatures.

**Required change →** Persist collision-resistant run/job IDs, tenant/project ownership, step/attempt states, immutable inputs/configuration, protected raw/canonical/output hashes, code and dependency digests, model/reference releases, parameters, seeds, worker/runtime identity and artifacts. Use durable dispatch, bounded worker concurrency, leases/heartbeats, retry budgets, idempotent artifact publication and recovery after worker failure. Commit outputs and success state atomically; hash integrity is separate from scientific truth and authorship.

Before confidential/patient-linked intake, enforce authentication and per-resource authorization across submission, status, artifacts, exports and audit queries; protected storage and transport including backups; managed keys; retention/deletion and legal-hold rules; redacted logs; sanitized client errors; and approved external destinations tied to data classification and provider agreements where applicable. Reject intake until these gates are satisfied.
