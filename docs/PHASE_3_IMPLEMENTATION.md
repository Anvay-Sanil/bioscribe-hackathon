**Supported application and code changes**

The sole supported composition is `backend/bioscribe/api.py`. It exposes authenticated `/v3/runs` submission, retrieval, cancellation, export, audit and provenance routes. `backend/bioscribe/worker.py` claims a durable SQLite job, runs computation in a killable spawned process, renews its lease, and commits results only if its attempt still owns the run. UUID4 identifiers, owner/tenant checks, idempotency conflicts, request/artifact hashes, immutable input identity and transactional artifact publication replace the request-local pipeline. Source, method-registry and dependency-lock snapshots are persisted with successful runs and can be retrieved through the authorized provenance route. These snapshots aid reconstruction; they are not an external trust anchor.

`backend/bioscribe/schemas.py` is the authoritative strict Pydantic contract. `docs/PHASE_3_OPENAPI.json`, frontend JSON Schemas, method records and `bioscribe-ai/src/lib/phase3/contract.ts` are generated by `python -m scripts.generate_contract`. Backend semantic validation and the frontend decoder enforce field identity, quantity/units, method/version, evidence category, fidelity record, assessment/execution status, coverage and absent predictive validation. No valid predictive-validation record is installed; the contract rejects attempts to promote predictions or reviewer approval into validated results.

`backend/bioscribe/identity.py` accepts explicitly declared protein/DNA/RNA, notes or molecular inputs. Sequence parsing records hashes, normalization operations, record count and original character offsets. Gaps, stops, ambiguous/nonstandard symbols, duplicate/empty FASTA records and unsupported encodings are rejected. Accessions require versions; taxonomy and source metadata remain user-supplied and unverified. Notes enter `needs_review` without extraction. Frameshift assessment is null, `not_assessed` and `unsupported_input` without the required nucleotide/reference context; there is no active frameshift implementation.

`backend/bioscribe/compute.py` and `registry.py` enable sequence length, overlapping residue-group composition, PS00107 pattern observations, a small set of RDKit descriptors, limited SMARTS observations and an explicitly unvalidated dimensionless descriptor-distance heuristic. The heuristic is target-independent, has no affinity units or confidence, and does not claim demonstrated ranking utility. The PS00107 translation uses the pinned pattern with overlapping starts and longest matching span per start. Its independent token-interpreter fixtures test correspondence; they are not a biological sensitivity/specificity study. Molecular identity retains isomeric representation, formal charge, fragments and assigned/unassigned stereochemistry; no salt stripping, protonation adjustment or tautomer normalization is performed.

Toxicity, Ames, hERG, PK, affinity, confidence, synthesis feasibility and structural predictions remain null and explicitly unassessed. A zero-match alert scan cannot create a safety conclusion. Failure of any scan rule yields a failed scan without a negative finding. ESOL is disabled: aromatic proportion is calculated as a descriptor, but the original ESOL equation/descriptor correspondence has not been re-established or scientifically validated.

`backend/bioscribe/metrics.py` supplies descriptive statistics with label provenance requirements, exclusions, average-rank ties, undefined constant correlations, unit restrictions and explicit enrichment tie handling. It never invents metrics. It is not a public predictive-validation endpoint. The previous benchmark service and scientific engines cannot be imported: their source is preserved behind explicit runtime failures for review.

The supported frontend consists of `/pipeline/new` and `/results/[id]`; `/` redirects to submission. It loads the actual UTF-8/FASTA file, submits the declared input, navigates using the returned run ID, polls persisted state and exports that run. Credentials remain in memory and must be re-entered after full reload. Other routes return an explicit disabled state. Legacy page sources were moved intact to `bioscribe-ai/legacy-ui/app/`; unrelated pre-existing edits remain preserved. Type/lint/build scope deliberately covers the supported application, not the retired prototype components. Default launcher scripts and Docker composition now select the supported API/worker. Legacy API entry points fail rather than serving their earlier claims.

**Startup for a fresh local public-data workspace**

From the repository root, create the launcher environment and install its lock:

```powershell
python -m venv .phase3-venv
& .phase3-venv/Scripts/python.exe -m pip install -r backend/requirements-phase3.lock
Push-Location backend
& ../.phase3-venv/Scripts/python.exe -m bioscribe.auth --auth-file data/principals.json --token-file data/local-token.txt --tenant local-public --subject local-researcher
Pop-Location
```

Provisioning refuses to overwrite existing credentials. Protect the credential files using the host's access controls; this helper does not establish a sensitive-data deployment. In separate terminals run `./start-backend.ps1`, `./start-worker.ps1`, and, from `bioscribe-ai`, `npm.cmd ci`, `npm.cmd run build`, `npm.cmd start`. Open `http://localhost:3000`, enter the locally provisioned token, and submit only public, non-sensitive inputs. The API binds to loopback; readiness requires matching dependencies, a valid principal configuration, database integrity and a recent worker heartbeat. Credentials are not hard-coded into the application or exported with results.

**Configured resource policy**

The single source is `backend/bioscribe/config.py`. Request body: 131,072 bytes with a 10-second receive deadline; compressed requests disabled. Sequences: 8 records, 10,000 residues each and 20,000 total. Molecules: 16 inputs, 2,048 SMILES characters each, 256 parsed atoms. Notes: 4,000 characters; model tokens: zero because LLM capabilities are disabled. Output artifact: 2,097,152 bytes. Queue: 32 queued/running jobs. Worker concurrency: one; computation timeout: 30 seconds; lease: 45 seconds; renewal: every five seconds; maximum claims: two. Audit reads expose at most 100 events with explicit completeness. These are conservative workstation policies, not empirically established capacity.

**Audit threat boundary**

The reference verifier assumes an attacker can rewrite the primary log and local cached receipts, but cannot rewrite the independently administered checkpoint store, obtain its signing key or substitute the live trusted checkpoint source. It compares history against the latest trusted count/head. An old valid signature alone is insufficient. Service unavailability returns unverified, never a pass. An authenticated checkpoint attests accepted log state; it does not prove that a biological statement is true or that a named person authored it. The local test service exercises the protocol/storage/access logic only; it does not demonstrate the required organizational or host isolation.

Phase 3 is submitted as reviewable implementation plus measured evidence and explicit open gates. Phase 4 must not be represented as already performed, and neither scientific release nor sensitive-data intake may be enabled on the strength of these software checks.
